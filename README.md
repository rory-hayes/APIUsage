# Usage Revenue Integrity OS Web App

Next.js app for the operator-assisted Usage Revenue Integrity OS audit MVP. The V0 product is invite-only and uses local JSON/file storage by default so paid-pilot workflows can be exercised without managed infrastructure.

## Local Setup

```bash
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

Seeded local users:

| Email | Role | Workspace | Password |
|---|---|---|---|
| `internal@usageintegrity.local` | Internal admin | Acme May 2026 audit | `pilot` |
| `customer@acme.ai` | Customer admin | Acme May 2026 audit | `pilot` |
| `member@acme.ai` | Customer member | Acme May 2026 audit | `pilot` |

Set `AUDIT_LOCAL_AUTH_PASSWORD` to override the shared local pilot password.

## Supabase Persistence

For hosted live testing, set `AUDIT_PERSISTENCE_DRIVER=supabase`. In that mode the JSON metadata stores use Supabase's REST Data API table `audit_json_documents`, and uploaded file bytes use `audit_upload_objects`.

Required server-side environment variables:

| Variable | Purpose |
|---|---|
| `AUDIT_PERSISTENCE_DRIVER` | Set to `supabase` to enable serverless persistence. |
| `SUPABASE_URL` | Project URL, for example `https://<project-ref>.supabase.co`. |
| `SUPABASE_SECRET_KEY` | Server-only Supabase secret key for the REST Data API. Do not expose as `NEXT_PUBLIC_`. |
| `AUDIT_SESSION_SECRET` | Strong random value for login cookies. |
| `AUDIT_DOWNLOAD_TOKEN_SECRET` | Strong random value for upload download links. |

Apply the SQL in `supabase/migrations` to the target Supabase project before enabling the driver.

## Auth0 Login

Hosted deployments can use Auth0 for identity while the app continues to authorize access through invited workspace users. When Auth0 is configured, `/login` sends users through `/auth/login`, `/auth/callback`, and `/auth/post-login`; the local password endpoint redirects to Auth0 instead of accepting credentials.

Required server-side environment variables:

| Variable                           | Purpose                                                                                                                                   |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `APP_BASE_URL`                     | Production app base URL, for example `https://api-usage-mu.vercel.app:443`.                                                               |
| `AUTH0_DOMAIN`                     | Auth0 tenant domain.                                                                                                                      |
| `AUTH0_CLIENT_ID`                  | Auth0 application client ID.                                                                                                              |
| `AUTH0_CLIENT_SECRET`              | Server-only Auth0 client secret.                                                                                                          |
| `AUTH0_SECRET`                     | 64-character hex secret used by the Auth0 SDK to encrypt session cookies.                                                                 |
| `AUTH0_UNVERIFIED_EMAIL_ALLOWLIST` | Optional comma-separated test email allowlist for Auth0 database users that cannot be marked verified. Leave unset outside test accounts. |

The Auth0 application must allow `https://api-usage-mu.vercel.app/auth/callback` as a callback URL and `https://api-usage-mu.vercel.app/` as a logout URL.

## Core Workflows

- Internal admin creates an invite-only workspace at `/admin/workspaces`.
- Internal admin creates customer invites at `/admin/workspaces`.
- Customer logs in, completes `/intake`, and uploads source files at `/uploads`.
- Internal admin reviews uploads, parses CSVs, maps accounts, reviews contract terms, runs checks, and approves/rejects findings at `/admin`.
- Customer sees approved findings at `/findings` and downloads evidence packs from `/evidence-pack`.
